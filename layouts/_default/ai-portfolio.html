01Delivery Hero · 2025–present

A support AI agent for ~70 country platforms

Impact
~80% less investigation time
Scale
~70 platforms, thousands of rps
Support load
Full-time → about one day a week

The problem

Our tier-1 services serve categories and products to platforms in ~70 countries at thousands of requests per second.

When a platform reports broken or missing products, the investigation crosses many services and teams. It took at least one engineer full time on support.

The solution

  • AI agent connected to Slack, repos, logs, traces, MCPs, and monitoring
  • MCP server + proxies to query all ~70 platforms
  • Safe by design: limited tools, rate limits, cost monitoring
  • ~80% less investigation time: support is now about one day a week

Who uses it

Platform teams who report an issue and engineers on support duty. Built so other teams can plug in their own MCPs.

My role

Designed and built the MCP server and proxies, made the rollout safe, and worked with staff and principal engineers to make it reusable for other teams.

Architecture & challenges

Rate limiting

The agent must never add load to services handling thousands of rps.

Tool harness

Limited, scoped tools: the agent can only do what we allow.

Cost monitoring

Track LLM and tool-call spend per investigation.

Networking

Proxies to reach ~70 isolated country platforms from one place.

Evaluation

Built into the workflow: if users can’t find what they need, they tag our team, or the agent tags us itself. Each tag is a miss to fix.

Next phase

From investigating to acting: syncing data between sources on engineers’ behalf, with an engineer approving each action.

02CHECK24 · 2024–2025

Experience recommender with LLM labeling

Live: erlebnisse.check24.de · Empfehlung
Used by
Every customer search on CHECK24 Erlebnisse
LLM
Async labeling, never in the search path
Resilience
Falls back to sorting by rating

The problem

Tours and activities come from different aggregators, with uneven quality and no consistent attributes.

Ranking decides what customers see and book, so plain sorting wasn’t enough.

The solution

  • Recommender ranks every search (“Empfehlung”)
  • LLM labels new and changed experiences every update
  • LLM runs async, never in the search path
  • Fallback ranking if the recommender is down
  • Planned: similarity search via vector DBs

Who uses it

Every customer search on CHECK24 Erlebnisse.

My role

Owned the backend and LLM infrastructure end to end: contracts, data flow, LLM labeling pipeline, rollout, monitoring. Partnered with the data scientist who owned the model.

LLM off the request path, ranking on it

No LLM in real time

Labeling runs async on new and changed items. Low-quality content is down-ranked, not rewritten live.

One source of truth

Labels go back through the write service into Elasticsearch, so search ranks in a single query.

Cost & resilience

Re-label only changed items, and only when a changed field affects ranking. Monitor LLM cost; fall back to sorting by rating.

Evaluation

For popular places the team knew the best experiences; we checked they ranked on top. Next: an automated eval harness.

03Side project · built for this conversation

Ask HR: a bilingual HR policy assistant

Live demo Admin dashboard Code on GitHub
Languages
German + English, cross-lingual
Grounding
Only official policies, always cited
Evals
Nightly and on every change

The problem

A large manufacturing site: thousands of employees on shifts and in offices, many not native German speakers.

Policies live in long PDFs and works agreements. HR answers the same questions again and again.

The solution

  • Answers only from official policies, with citations
  • German and English, cross-lingual retrieval
  • Filtered by employee group (shift / office)
  • Says “I don’t know” and escalates to HR

Who it’s for

Employees and HR business partners. The demo runs on synthetic policies for a fictional company.

My role

Everything: framing, spec, agent and retrieval, evals, monitoring, deployment.

See it in action

German question, cited answer, sources, group switch, refusal and escalation

ask-hr-assistant.vercel.app

Every answer comes with its source

  1. 01 · Cited answerEvery fact links to a numbered policy chunk.
  2. 02 · Sources panelSection path, language and snippet for each source.
  3. 03 · Employee groupShift vs office filters what can be retrieved.
  4. 04 · FeedbackThumbs up / down feed the quality dashboard.

What HR and engineering see

  1. 01 · Quality & SLOsRefusal and escalation rate, feedback ratio, p95 latency, time to first token and error rate against their targets.
  2. 02 · CostSpend today and over 7 days, with a daily budget guard behind it.
  3. 03 · Content gaps for HRTop unanswered questions show where policies are missing or unclear.
  4. 04 · PseudonymousNo user identity stored; questions PII-redacted before logging.

A tool-calling agent over hybrid retrieval

Why hybrid retrieval

HR text is full of exact terms like Nachtzuschlag or paragraph numbers that pure vector search misses. A relevance threshold makes it refuse instead of guessing.

Why an agent with tools

Instead of a fixed pipeline, it can search again, combine two policies, or decide to escalate. The model is configurable, so it can run on an EU-hosted or self-hosted model.

  • Next.js
  • TypeScript
  • Vercel AI SDK
  • Postgres + pgvector (Neon)
  • Langfuse
  • GitHub Actions
  • Vercel (Frankfurt)
  • Docker for self-hosting

Measured before tuned, built for EU policies

Evaluation harness

A golden set of questions in DE / EN: cross-lingual, group-specific, unanswerable and prompt-injection cases. Runs nightly and on every change; LLM-as-judge scores the answers.

What it measures

  • Retrieval: recall@k and MRR
  • Answer correctness and faithfulness to sources
  • Citation validity
  • Refusal accuracy: no guessing, no false refusals
  • Prompt-injection resistance and PII handling
  • Latency and cost per query

In production

  • Trace per request: retrieval, tokens, cost
  • Refusal rate, feedback, p95, daily cost
  • Top unanswered questions: a content-gap report for HR
  • Nightly eval to catch model drift

Built for EU policies

Personal data is redacted before it reaches the LLM or the logs, and logs are kept only for a limited time. The assistant informs and never decides about people, and users always know they are talking to AI. Metrics are aggregated, with no tracking of individual employees.

04Side project · live on Google Play

Wortaso: learn German vocabulary by example

wortaso.app Google Play
Words
12,000+ with examples
Learners
~1,000, beginner to B2
Built
Solo, end to end

The problem

Word lists teach words without context, and every noun’s der / die / das has to be memorized too.

I had the same problem learning German.

The solution

  • 12,000+ words, each with example sentences
  • Friendly UI where colors make der, die, das stick
  • Spaced repetition, exam lists, no ads
  • Examples + translations from a German model run via Ollama

Who uses it

~1,000 German learners, beginner to B2.

My role

A side project for my own German journey. Built it alone: app, database, content pipeline, release.

Generate in batch, ship to the app

Batch, not live

Generated offline on Colab GPUs: no inference cost per user, fast app.

Model choice

General models then couldn’t write good German examples, so I ran a German-specific model with Ollama. It was slow, so batching on GPUs mattered.

Evaluation

User feedback today. Next phase: LLM-as-judge scoring article, grammar and level fit.

Team metrics: fewer dark searches, higher CTR, fewer searches per user.
